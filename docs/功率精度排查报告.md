## 二、实测真值（LibreHardwareMonitor）

在空闲态抓到的一组关键真值：

| 传感器 | 实测值 | 含义 |
|---|---|---|
| CPU Package | **17.7 W** | 整个 SoC 封装功耗（含 CPU+GPU+IO） |
| GPU Core | 16.0 W | **已包含在 Package 内**，不可重复计 |
| GPU SoC | 4.0 W | 同上 |
| CPU Total | 10.2 % | 16 线程平均 |
| Core (Tctl/Tdie) | 55.9 °C | CPU 温度 |
| Charge Rate | 42.0 W | 电池充入功率（LHM 侧） |

> ⚠️ **AMD APU 关键特性**：LHM 的「Package」是 SoC 封装总功耗，
> 独立累加 GPU Core / GPU SoC 会导致**重复计算**。正确做法是以 Package 为准。

## 三、问题清单（6 项）

### ① GPU 项读数恒为 0（严重）
C++ 版用 `Win32_PerfFormattedData_GPUPerformanceCounters_GPUEngine` 中
`engtype_3D` 各实例 **求和**，实测恒为 `0.0%`；而真实 GPU Core 有 16W。
**GPU 功耗在总功耗里完全丢失。**

根因有二：
- 多进程多队列的 engine 实例求和后再截断到 100%，数值本身不可靠；
- `engtype_3D` 在纯桌面空闲时确实为 0，但 GPU 仍在耗电（显示输出、视频解码等）。

### ② 模型结构缺失「基础功耗」（严重）
对照旧版 PowerShell：
```
旧版：整机系统 = SoC功耗 + BaseOverheadW(默认 5W，含自学习标定)
C++：整机系统 = SoC估算           ← 基础功耗项整个丢失
```
主板、内存、SSD、屏幕、网卡、VRM 供电损耗约 5~6W，这部分被系统性漏掉。

### ③ 17W 基准 + 线性系数不准（中等）
- 实测空载 SoC = **17.7W**，公式给的基准 17W 看似接近；
- 但公式是**线性**的（每 1% CPU 加 0.2W），真实 APU 是**非线性**：
  低负载陡升、高负载趋缓（受 PPT 上限约束）。
- 线性外推在 CPU=100% 时给出 17+20=37W，而实测满载仅 30~36W → **高负载过高估**。

实测偏差：
| 场景 | 公式估算 | 实测 SoC | 偏差 | 相对误差 |
|---|---|---|---|---|
| 空闲态 | 19.42 W | 17.70 W | +1.72 W | **+9.7 %** |
| 空闲态2 | 19.04 W | 17.70 W | +1.34 W | **+7.6 %** |

### ④ 充电功率直接相加，未扣损耗（中等）
锂电充电效率约 85~90%。`总功率 = 充电功率 + 系统` 把适配器输入算成了
`系统 + 充电`，实际应是 `系统 + 充电/效率`。30.5W 充电功率中约 3~4.5W 变热散掉，
直接相加会**低估**适配器输入（此处方向与 ② 相反，两者部分抵消）。

### ⑤ ChargeRate 冷启动读 0（轻微）
实测：00:21 首次探测读到 `ChargeRate = 0`，00:27 再读得到 `30763 mW = 30.76 W`。
这是 WMI 服务冷启动时首查未就绪所致。原代码 `d > 0` 判定会把真实充电
误判为「无流动」，界面功率瞬间塌到纯估算值。

### ⑥ VARIANT 解析未区分数值类型（轻微）
原代码把 `VT_I4 / VT_UI4 / VT_I2 / VT_UI2` 一律用 `v.lVal` 读取。
小值下碰巧正确，但属潜在 UB，`VT_UI4` 应用 `ulVal`、`VT_UI2` 用 `uiVal`。

## 四、已实施的修正

### 4.1 模型重构（`EstimateSocW` / `EstimateSystemW`）
```cpp
static const double kSocIdleW  = 17.7;   // 空载 SoC 封装功耗（LHM 实测）
static const double kBaseOverW = 6.0;    // 非 SoC 基础功耗
static const double kChgEff    = 0.90;   // 电池充电效率

static double EstimateSocW() {
    double cpu = g.cpuPct > 0 ? g.cpuPct : 0;
    double gpu = g.gpuPct > 0 ? g.gpuPct : 0;
    double load = cpu + 0.5 * gpu;              // GPU 权重折半（同封装共享）
    if (load < 0) load = 0;
    double soc = kSocIdleW + 1.35 * sqrt(load); // 非线性拟合
    if (soc > 34.0) soc = 34.0;                 // 本机 SoC 封装上限（PPT）
    return soc;
}
static double EstimateSystemW() { return EstimateSocW() + kBaseOverW; }
```

### 4.2 充电总功率扣损耗
```cpp
if (g.chargeW > 0.05) return sys + g.chargeW / kChgEff;
```

### 4.3 GPU 口径重写
从「3D 求和后截断」改为「按 GPU 实例分组、组内取最大、跨引擎取最大」，
并扩展识别 `engtype_3D` + `engtype_Compute`。

### 4.4 电池读取抗抖动
ChargeRate / DischargeRate 读到 0 且处于插电态时重试 3 次（间隔 150ms），
仍为 0 则保持上次有效充电值，避免界面在 30W ↔ 0W 之间闪跳。

### 4.5 VARIANT 类型精确解析
```cpp
case VT_UI4: *out = (double)v.ulVal;  ok = true; break;
case VT_I4:  *out = (double)v.lVal;   ok = true; break;
case VT_UI2: *out = (double)v.uiVal;  ok = true; break;
case VT_I2:  *out = (double)v.iVal;   ok = true; break;
case VT_UI8: *out = (double)v.ullVal; ok = true; break;
case VT_I8:  *out = (double)v.llVal;  ok = true; break;
```

## 六、待办：用真值精调系数

当前系数 `1.35`（sqrt 斜率）与 `34.0`（上限）是**依据「空载 17.7W、满载 30~36W」
推算的初步值**。要精确标定需在多负载点采集 LHM 真值：

1. 启动 `启动LHM传感器.cmd`（管理员，开放 `http://127.0.0.1:8085/data.json`）
2. 运行 `sample.py`：在空载 / 25% / 50% / 75% / 100% 五档负载下各采若干点
3. 运行 `fit.py`：以 Package 为真值做最小二乘拟合，输出最优 `kSocIdleW / 斜率 / 上限`
4. 回填到 `main.cpp` 重新编译
